# 1top 제품 영상 v7.0.0

랜딩 페이지(https://1top.si) v7.0.0에 쓰는 제품 영상과 정지 화면을 다시 만드는 스크립트입니다. 프론트엔드 커밋의 실제 화면에 지어낸 데모 데이터를 띄우고, 정해진 시간표대로 조작하면서 그 앱의 창만 녹화합니다.

- **데모 데이터**: `scripts/demo-state.mjs`가 만듭니다. 프로젝트와 계정은 지어낸 것이고, 사용량은 실제 사용 모양을 따릅니다. 웹 `/app?demo`와 휴대폰 체험 모드도 같은 생성기를 씁니다.
- **데모 시각**: 모든 장면과 정지 화면은 데모를 한 시각(`demoNow` 1800000000)에 멈춰 두고 찍습니다. 웹 `/app?demo&demoNow=1800000000`, 휴대폰 촬영과 같은 시각이라 모든 화면의 숫자가 같습니다. 녹화하는 동안 앱과 페이지의 시계는 그 시각에서 시작해 흐르므로, 대화 장면의 전달 단계와 보고 시각은 그대로 움직입니다.
- **기준 커밋**: 모든 장면을 `3e41fe5`로 다시 만들 수 있습니다. `08748ca` 뒤의 커밋은 대화 화면과 대화 데이터만 바꿨습니다. 이 커밋은 웹·데스크톱·휴대폰 데모를 하나의 데모 세계로 묶었고, 그 앞 커밋들의 다음 내용을 모두 담고 있습니다.
  - 윈도우 퀵뷰 로고(`43da216`)
  - 실제 수집기 모양의 데모 상태(`69c9a89`)
  - 대시보드 번역(`bf64d47`, `2dccd33`)
  - 정수 계정 한도(`29a6da0`)
  - 언어별로 맞춘 세션 표 열 폭(`939eb05`, `d5b1952`)
- **장면별 커밋**: `conversation-ko`는 `3e41fe5`(보내기 확인창 없이 바로 보냄, 2026-10-30)로 다시 찍었습니다. `menu-ko`도 `3e41fe5`로 14.4초 길이로 다시 찍었습니다(2026-10-30). 히어로가 쓰는 `menu-panel-ko.png`는 히어로를 건드리지 않으려고 예전 파일을 그대로 두었습니다. `conversation-en`·`conversation-zh`는 아직 `37066df`(대화 화면 개편과 하나의 대화 대본, 보내기 전 확인창 있음)로 찍은 것이고, 한국어판이 확정되면 `3e41fe5` 이후 빌드로 다시 찍습니다. 나머지 15개 영상과 메뉴 패널·윈도우 퀵뷰·웹 정지 화면은 `08748ca`로, 모두 위의 데모 시각에서 찍었습니다. `conversation`에는 아래 '보내기 전 포커스 해제'가 들어 있습니다. 휴대폰 정지 화면은 프론트엔드가 같은 시각으로 찍은 `output/landing-phones_v7.2.0`을 절반 크기 JPEG로 줄인 것입니다.
- **창 크기**: 대시보드 창은 가장 넓은 화면에 1640×1068로 띄웁니다. 내장 디스플레이는 1512포인트라서, 영어 머리글·배지·세션 이름이 다 들어가지 않습니다.

## 다시 만드는 방법

필요한 것은 Xcode, Node, `ffmpeg`, Python의 Pillow와 Playwright, 그리고 터미널 앱의 화면 기록 권한입니다.

```bash
python3 scripts/showcase_v7.0.0/prepare_capture.py 3e41fe5          # 한 번만 실행합니다
for scene in dashboard gauges conversation accounts customize menu; do
  for lang in ko en zh; do python3 scripts/showcase_v7.0.0/record.py $scene --lang $lang --now; done
done
python3 scripts/showcase_v7.0.0/stills.py tray
(cd site && npx vite --host 127.0.0.1 --port 5197) &                # 웹 정지 화면용
python3 scripts/showcase_v7.0.0/stills.py web
```

녹화하는 동안 가장 넓은 화면의 왼쪽 위에 녹화 전용 창이 장면마다 20초쯤 뜹니다. 메뉴 막대 패널은 메인 화면의 메뉴 막대 아래에 뜹니다. 다른 앱의 창은 녹화에서 빠집니다.

`record.py` 옵션은 다음과 같습니다.
- `--replace`: 이미 있는 v7.0.0 결과를 덮어씁니다. 이 옵션이 없으면 기존 파일을 지키고 멈춥니다. 이전 버전 폴더는 건드리지 않습니다.
- `--now`: 바로 녹화합니다. 이 옵션이 없으면 매분 8초에 시작합니다.
- `--keep`: 원본 ProRes 녹화를 `build/showcase_v7.0.0/takes/`에 남깁니다.
- `--demo-now <초>`: 데모 시각을 바꿉니다. 기본값은 1800000000입니다. `stills.py`는 `--demo-now=<초>`로 받습니다.

녹화 기록은 `build/showcase_v7.0.0/`에 남습니다.
- `<장면>-<언어>.log`: 앱 로그
- `<장면>-<언어>.film.log`: 녹화기 로그
- `<장면>-<언어>.values.txt`: 녹화가 끝날 때 표에 보이던 세션별 값

## 녹화 전용 앱에서 바꾼 점

- **데모 시계**: `ONETOP_DEMO_NOW`가 있으면 패널의 시계(`DashboardModel`의 `now`, 보고 시각, 새로 고침 판단)와 대시보드 페이지의 `Date`가 그 시각에서 시작해 흐릅니다. 앱 자체에는 이런 옵션이 없어서 녹화 사본에서만 바꿉니다.
- **연결과 제어**: 항상 테스트 모드로 실행하고 합성 서버(18868)에만 연결합니다. 수집기를 시작하지 않습니다. 세션 제어와 로그인할 때 실행 설정은 동작하지 않습니다.
- **대시보드 설정**: 대시보드 WebView는 저장소를 남기지 않습니다. 시작할 때 대시보드가 쓰는 키 `onetop.dashboard.v1`에 장면의 언어를 넣습니다. `gauges` 장면에는 열 순서와 기간 열 너비도 넣습니다.
- **패널 시작 상태**: 메뉴 막대 패널은 녹화 전용 앱의 설정 영역(`capture-app`)에서 다크 테마와 장면의 언어로 시작합니다. 설치된 앱의 설정(`si.1top.companion`)은 읽지도 쓰지도 않습니다. 녹화 순서에서 패널의 테마·언어 버튼은 누르지 않습니다.
- **조작 방식**: 클릭, 끌기, 스크롤, 기간 막대는 마우스나 키보드와 같은 DOM 이벤트로 보냅니다. 기간 막대는 끌 때처럼 한 칸씩 `input`을 보내고 놓을 때 `change`를 보냅니다.
- **대화 장면**: 보내는 글과 사진은 데모 세계의 대본에서 가져옵니다. 사진은 파일 입력에 `DataTransfer`로 넣습니다. 메일함을 읽는 간격은 5초에서 1초로 줄였습니다. 영상에서 전달 상태가 바뀌는 순간이 늦게 보이지 않게 하려는 것입니다(앱에서는 최대 5초 늦게 보입니다). 이것이 렌더러 코드에서 바꾼 유일한 점입니다.
- **보내기 전 포커스 해제**: 보내기 직전에 입력란의 포커스를 풉니다. 그대로 두면 macOS가 커서 옆에 입력 소스 표시기를 그리고, 이 표시기가 AI의 답이 올라온 뒤에도 같은 자리에 남아 글자를 가렸습니다(`37066df`까지는 확인 창이 닫힐 때 포커스가 입력란으로 돌아오며 생겼습니다). 확인 창이 없어진 `3e41fe5`부터 녹화 순서에서 확인 창을 누르는 단계는 뺐습니다. 녹화 앱 설정 영역의 `TSMLanguageIndicatorEnabled`로는 꺼지지 않았습니다. 시스템 설정은 바꾸지 않았습니다.
- **패널 열기**: 메뉴 막대 패널은 포인터 위치와 상관없이 메뉴 막대 아이콘을 누른 것처럼 아이콘 아래에 엽니다.
