# 다중 계정 유지·한도 수집·자동 전환 작업 v1.0.0

2026-10-31. 사용자가 OmniRoute 검토 결론을 확인하고 이 기능을 백엔드 작업에 추가하도록 지시했다.
담당은 Codex다. 현재 상태는 **작업 등록 및 코드 검토 완료, 아래 신규 기능 구현 전**이다.
프론트 디자인과 기존 계기판 수정은 Claude 담당 범위를 유지한다.

## 구현 순서

1. **계정 관리와 로그인 유지**
   - 제공자·계정·조직/워크스페이스 식별자와 표시 이름을 관리한다.
   - 계정 인증 정보와 모델별 한도 풀을 분리하고, 계정 전환으로 기존 계정 기록이 바뀌지 않게 한다.
   - 기존 1top의 별도 CLI 프로필, Keychain helper, 갱신 잠금, 계정 변경 검사를 이어 사용한다.
   - 갱신 시점을 관리하고, 여러 요청의 갱신을 하나로 모으며, 저장 직전 버전을 비교해 오래된 토큰이 최신 토큰을 덮어쓰지 않게 한다.
   - 제공자 오류·일시적 연결 실패에 재조회 간격을 적용하고 계정별 마지막 정상 보고를 보존한다.
2. **계정별 한도 수집**
   - 계정에 속한 5시간·주간·일간·월간 및 모델별 풀의 사용률·초기화 시각·조회 상태를 유지한다.
   - GLM 키 식별표와 Agy 풀 이름을 로그인 계정명과 구분하고, 제공자별 계정 식별 경로를 연결한다.
   - 한도 없음, 미보고, 조회 실패, 오래된 보고를 데이터에서 구분한다.
   - 실제 한도 소진과 일시적 요청 빈도 제한을 구분해 계정 가용 상태를 계산한다.
3. **로컬 게이트웨이와 자동 계정 전환**
   - CLI의 모델 요청을 받아 선택된 계정으로 전달하는 로컬 요청 경로를 추가한다.
   - 같은 제공자·모델에서 계정 우선순위, 전환 임계값, 잔여 한도, 초기화 시각으로 계정을 선택한다.
   - 정상 사용 중인 세션의 계정을 유지하고, 해당 계정이 소진되면 다른 가용 계정으로 전환한다.
   - 요청마다 실제 사용 계정을 사용량 기록에 남겨 전환 전후 집계가 섞이지 않게 한다.
   - 스트리밍 도중과 응답 전 오류를 구분하여 이미 전달한 응답·실행을 중복 재시도하지 않게 한다.

## 완료 확인

- 여러 계정이 동시에 유지되고 한 계정 갱신이 다른 계정을 바꾸지 않는다.
- 동시 갱신·토큰 교체·프로세스 재시작 후에도 최신 인증 정보를 보존한다.
- 계정 A의 한도 도달 → 동일 모델의 가용 계정 B 선택 → 실제 사용 계정 기록을 통합 검사한다.
- 5시간/주간/모델 풀별 제한과 초기화 이후 재사용을 각각 검사한다.
- 실제 계정 수집 검증과 합성 응답을 이용한 전환 검증 결과를 구분하여 기록한다.
