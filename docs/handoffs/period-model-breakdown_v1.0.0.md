# 기간별 모델 집계 계약 v1.0.0

메뉴바는 현재 세션 목록에 없는 사용량을 `종료된 세션`으로 묶고 있었다.
수집된 이벤트에는 모델명이 남아 있으므로, 기간별 집계에 기록 당시 모델과 실행 도구별 내역을 추가한다.

## 로컬 API

`GET /api/state`와 `GET /api/state?period=...`의
`period_usage.windows[].by_model`은 다음 배열이다.

```json
[
  {
    "kind": "Claude",
    "model": "claude-opus-5-5",
    "tokens": [100, 200, 30, 40],
    "session_count": 2
  }
]
```

- `tokens` 순서는 기존 기간 벡터와 같은 fresh, cached, written, output이다.
- 종료 여부와 무관하게 해당 기간의 모든 수집 이벤트를 포함한다.
- 같은 세션에서 모델이 바뀌면 각각의 기록 당시 모델에 나눠 합산한다.
- 같은 모델을 다른 도구에서 사용하면 `kind`별로 구분한다.
- `model: null`은 해당 이벤트에 모델 정보가 없는 경우다. 종료됐다는 뜻이 아니다.
- 토큰 합계 내림차순이며 동률이면 kind, model 순이다.
- 각 토큰 성분의 합계는 해당 window.tokens와 일치한다.
- session_count는 해당 도구·모델을 사용한 고유 세션 수다. 모델 간 합산하면 중복될 수 있다.
- 6개 기본 기간, 사용자 지정 기간, 전체 기록에 동일한 계약을 적용한다.
- 현재 세션 목록에 과거 세션을 재삽입하지 않으며 제어 가능한 세션 목록도 바꾸지 않는다.

프론트는 by_model이 있으면 이를 사용한다. 빈 배열은 보고된 사용 없음이며,
필드가 없는 구버전 서버에서만 기존 세션 기반 계산으로 돌아간다.
이는 로컬 API 추가 계약이며 원격 relay periods에 자동 전파되는 필드는 아니다.

## 검증

- Python 회귀 테스트 442개 통과.
- 종료된 세션, 모델 변경, 같은 모델의 서로 다른 실행 도구, 정보 없는 모델,
  기간 경계와 미래 이벤트 제외, 사용자 지정·전체 기간을 검증했다.
- 실제 monitor.sqlite를 읽기 전용으로 조회해 6개 기간 모두 모델 합계와 전체 벡터의 일치를 확인했다.
- frontend-freeze_v1.23.1.sha256 132개 모두 일치.
- 프론트 파일 수정과 앱 빌드·설치·배포는 수행하지 않았다.
